# 直播检测与通知

[返回 README](../README.md)

## 通知卡片

![开播卡片](images/card-start-amis.png)

开播／下播通知默认渲染成图片卡片，包含主播头像、直播间标题、直播封面、直播间二维码、开播时间或本场时长，文案用《鸣潮》角色**爱弥斯**的口吻（星炬学院学生、隧者适格者、电子幽灵，官方性格描述为「活泼俏皮」）。

**卡片需要外部文转图服务**，插件本身不内置浏览器：

```sh
docker run -itd -p 8999:8999 soulter/astrbot-t2i-service:latest
```

部署好后在 WebUI「直播订阅 → 通知卡片 → 文转图服务地址」填写地址。NapCat 与 AstrBot 装在同一台机器时通常填 `http://127.0.0.1:8999`；不同容器要填宿主机 IP 或容器名。

**渲染服务所在环境需要中文字体和彩色 emoji 字体**，否则卡片上的中文会变方框、emoji 会变黑白或空白：

```sh
apt-get install -y fonts-noto-cjk fonts-noto-color-emoji
```

部署完在 WebUI 点「渲染服务自检」，会渲染一张含中文、emoji 和二维码的测试卡并报告耗时。

### 降级顺序

卡片渲染失败不会导致漏通知，按下面的顺序退回：

1. 卡片图片 + 爱弥斯文案
2. 直播封面图 + 爱弥斯文案（未配置服务、服务不可达、超时、返回非图片时）
3. 纯文字（沿用 1.4.x 的 `【B站开播通知】…` 格式）
4. 发送本身失败 → 记录为「结果未知」，不自动重发（保持原有行为）

渲染失败**不写发送记录、不消耗 30 分钟去重窗口**，下一轮检测仍会正常通知。

### 可调项

| 设置 | 说明 |
| --- | --- |
| 使用图片卡片 | 关闭后回到纯文字 |
| 通知口吻 | 爱弥斯（默认）／软萌／朴素（朴素即 1.4.x 的纯文字格式） |
| 卡片配色 | 爱弥斯蓝粉／B站粉／极简 |
| 卡片装饰 | 自动（有自备贴纸就用）／仅内置装饰／不叠加贴纸 |
| 文转图服务地址 | 留空即只发「封面 + 文案」 |
| 自定义请求 JSON | 对接非 AstrBot 契约的渲染服务时使用，用 `{{html}}` 占位 |

### 自备贴纸

把图片放进插件目录 `assets/card/custom/`，重启或重载插件后生效。文件名前缀决定叠加位置：

| 前缀 | 位置 |
| --- | --- |
| `top-` | 卡片顶部装饰带 |
| `tag-` | 主播名字右侧的徽章 |
| `corner-` | 卡片右下角 |

单个文件不超过 2MB、目录合计不超过 10MB，超出会被跳过并在预览里提示。内置装饰只有自绘的星星、音符、圆角与渐变，插件不分发角色素材；贴纸版权请自行确认。

### 性能与缓存

- 同一条通知**只渲染一次**，发给多个群时复用同一张图片。
- 卡片按内容哈希缓存在数据目录 `live-cards/`，同一主播同一标题的重复通知直接复用。
- 缓存按「卡片缓存上限」清理，另外兜底清理 7 天前的旧卡片。
- 封面与头像走插件已有的请求通道（复用请求间隔与风控冷却），内联成 data URI 发给渲染服务，渲染服务不需要访问 B站图床。

## 配置

在 WebUI「直播订阅」添加主播，可用 UID、直播间号、个人空间或直播间链接。最多 20 位主播，每位最多 50 个通知群。订阅里的 QQ 群独立于链接识别白名单／黑名单，机器人需要实际加入这些群并有发言权限。

新增或重新启用订阅时先读取当前直播状态作为基线。已在进行的直播不会自动补发开播，需要时点击手动开播。

检测总开关默认关闭，每轮结束后等待的间隔默认 60 秒，可设为 30–3600 秒。查询、消息发送或风控冷却较慢时，实际间隔可能延长。

## 多个每日时段

打开「仅在指定时段检测」，点击「添加时间段」，填写后保存。最多 12 段；开启限制时至少有一段。旧单时段自动保留为第一段。

固定按北京时间 UTC+8，包含开始时刻，不包含结束时刻。支持 `22:00–02:00` 这样的跨午夜时段；多个时段按并集生效，重叠不额外查询。开始与结束不能相同，全天检测请关闭时段限制。

默认开启「发现开播后持续检测到下播」：时段外只跟踪已知开播主播，连续两次确认未直播后结束跟踪。查询失败不当作下播，轮播视为未直播。关闭该选项后，到时段结束即停止查询，即使主播仍在直播。

## 手动控制

- **手动开始检测**：对点击时启用的主播开始检测，允许超出时段。每位主播确认下播后恢复按时段运行；尚未开播的主播继续等待，直到手动停止。
- **手动停止检测**：停止后续自动查询，优先于检测时段和开播跟踪，重启后保持。已经发出的请求或已提交 QQ 的消息不能撤销。
- **恢复自动时段**：按保存的时段和跟踪选项运行。

所有模式继续遵守请求间隔和 412／429 冷却，手动开始不会清除冷却。

## 手动通知与失败补发

点击对应主播的「手动发开播／下播」，页面会显示主播和目标群，核对后点「确认发送」。这会直接排队群消息，使用已缓存的房间资料，不请求 B站。缓存标题可能不是最新值；下播时长按已知时间估算，缺少开播时间时不显示。

手动消息不会修改真实检测状态，也不会恢复被停止的检测。若同时需要继续检测，请另外操作检测按钮。有未保存的表单时需要先保存或刷新。

最近通知按群记录排队、发送成功、失败／结果未知等状态。一个群失败后继续发送其余群；同一主播正在手动发送时不重复排队。修改或删除订阅会阻止任务继续向旧配置提交群消息。

超时可能是发送成功但回执没回来，不自动重发。检查群消息后，可以选择「仅补发此群」，沿用原记录文本和原群；原群已从订阅移除时拒绝补发。

手动通知与后续自动检测之间有 30 分钟短时去重，避免同一变化立即重复通知已覆盖的群。通知记录在提交 QQ 前保存，重载时未取得回执的记录标记为结果未知，不自动重发。

配置、缓存房间与状态记录保存在插件数据目录的 `live-subscriptions.json`。最多保留 100 条结束记录；排队／发送中的记录额外保留。
