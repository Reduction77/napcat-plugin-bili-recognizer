# B站链接识别 · NapCat 原生插件

为 QQ 群聊和私聊提供 **B站链接解析、扫码登录、视频下载与直播开播／下播通知**，内置 WebUI 控制台。

**当前版本：1.5.2** · **维护者：朱朱白白** · **许可证：ISC**

[安装](#安装) · [使用方法](#使用方法) · [直播通知](#直播通知) · [常见问题](docs/troubleshooting.md) · [开发与打包](docs/development.md) · [更新日志](CHANGELOG.md)

## 功能

| 功能 | 说明 |
| --- | --- |
| 链接识别 | 视频 BV／AV、b23 短链、QQ 小程序 JSON／XML 分享等 |
| 内容回复 | 封面、标题、作者、简介、统计与规范链接；图片发送失败时尝试纯文字 |
| 扫码登录 | 在 WebUI 生成二维码，用 B站 App 扫码保存账号凭据 |
| 视频下载 | 普通视频、分 P，360P／480P／720P／1080P 清晰度上限 |
| QQ 视频发送 | 指令下载或分享链接后自动下载，完成后发送回原会话 |
| 直播通知 | 多主播、多群开播／下播通知，记录各群发送结果 |
| 通知卡片 | 开播／下播渲染成图片卡片：直播封面、头像、二维码与装饰，爱弥斯人设文案 |
| 多检测时段 | 每天最多 12 段，北京时间，支持跨午夜；默认发现开播后持续跟踪到下播 |
| 手动控制 | 开始／停止检测，手动发送开播／下播通知，失败记录单群补发 |
| WebUI | 账号、配置、群范围、链接测试、下载、直播、缓存与日志管理 |
| 请求与诊断 | 共享请求间隔、412／429 冷却、下载错误详情和脱敏诊断导出 |

除普通视频外，也实现了动态／图文、番剧／剧集、直播间、专栏／笔记、用户主页、收藏夹、音频／歌单和文集的信息获取。话题、合集／系列、课堂目前提供类型识别与规范链接。具体可用性取决于 B站接口、登录状态及内容权限。

本插件运行在 NapCat 内，无需 AstrBot、独立 Python 服务、额外 OneBot 连接或新的 WebUI 端口。二维码库随包提供，前端不需要编译，也不依赖在线 CDN。

## 运行要求

- 支持原生插件和 WebUI 路由的 NapCat。`package.json` 声明最低版本为 **4.14.0**，尚未逐个验证所有版本。
- NapCat 的 Node.js 运行环境 **20.3.0 或以上**；开发测试使用 Node.js 24。
- 运行 NapCat 的服务器能访问 B站接口和媒体节点，机器人已登录且有目标群发言权限。
- **480P 及以上下载需要服务器上的 FFmpeg**；360P 遇到分段或需要重新封装的流时也可能需要。

识别、登录与直播通知不依赖 FFmpeg。只把 FFmpeg 装在打开网页的电脑上，不会让远程 NapCat 获得它。

## 安装

### 使用安装包

1. 获取 `napcat-plugin-bili-recognizer-1.5.2.zip`。维护者可以按[打包文档](docs/development.md#生成插件安装包)从源码生成。
2. NapCat 插件管理若提供本地 ZIP 导入，使用该入口安装；也可以手动解压到当前实例的插件目录。
3. 手动安装的最终层级应是：`plugins/napcat-plugin-bili-recognizer/package.json`，同级有 `index.mjs`、`lib/` 和 `webui/`。避免多套一层目录。
4. 刷新插件列表并启用 **B站链接识别**，必要时重启 NapCat。

### 直接使用源码

将本仓库的项目文件夹放入当前 NapCat 实例的插件目录，并命名为 `napcat-plugin-bili-recognizer`。入口 `index.mjs` 必须位于该文件夹根目录。

**无需 `npm install`，无需构建。** 直接双击 HTML 或执行 `node index.mjs` 不会启动插件服务，入口需要由 NapCat 加载。

### 打开 WebUI

先登录 NapCat 管理面板，在插件扩展页面中找到 **B站识别控制台**。也可在同一管理面板地址后拼接：

```text
/plugin/napcat-plugin-bili-recognizer/page/dashboard
```

使用实际的管理面板域名、端口和反向代理前缀。本插件复用 NapCat 的页面、静态资源与鉴权机制，参见 [NapCat 配置与 WebUI 文档](https://napneko.github.io/develop/plugin/start-webui)。

### 更新

停用旧插件，将新文件完整覆盖到原插件目录，**保留 NapCat 配置和插件数据目录**。重启 NapCat 后，浏览器 Ctrl+F5 强制刷新，确认版本号已更新。不要同时保留两份相同插件。

## 使用方法

### 识别链接

使用另一个 QQ 账号，在机器人可响应的群或私聊中发送 B站视频链接、短链或 BV／AV 号。插件忽略机器人自己发送的消息。

默认开启群聊和私聊识别，同一会话相同内容的重复回复间隔为 120 秒。可在 **插件配置** 设置群白名单／黑名单、忽略用户、封面、简介和解析数量。

WebUI 的 **链接测试** 只预览解析结果，不会向 QQ 发送消息。

### 扫码登录

打开 **B站账号 → 生成登录二维码**，使用 B站 App 扫描并在手机确认。保存成功后，点击 **检查登录状态** 查看账号是否有效。

登录凭据由本插件在服务器本地保存。自带 WebUI 不回传已保存 Cookie；NapCat 原生配置表单仍可以读取配置。当前不自动刷新失效的账号凭据，失效后可重新扫码。

**扫码登录不能保证消除所有 412。** 默认请求最小间隔为 1.5 秒，遇到风控后进入冷却；不要通过反复点击测试、下载来连续重试。详细处理见[常见问题](docs/troubleshooting.md)。

### 下载视频

在允许响应的会话发送以下指令。BV 号与短链是格式示例，请替换为实际视频：

```text
/bili下载 BV1xx411c7mD
/bili下载 https://www.bilibili.com/video/BV1xx411c7mD P2
/下载视频 https://b23.tv/你的短链
```

`P2` 表示第 2 个分 P，不写时默认 P1；QQ 指令也读取完整链接中的 `?p=2`。一次只下载一个分 P，成功后发送回原会话。

| 下载模式 | 行为 |
| --- | --- |
| 仅下载指令（默认） | 收到下载指令才创建 QQ 下载任务 |
| 识别后自动下载 | 回复普通视频信息后自动下载，也支持指令 |
| 关闭 QQ 下载 | 关闭聊天触发，仍可从 WebUI 创建任务 |

WebUI 路径：**视频下载 → 输入链接／编号 → 选择分 P → 加入下载队列**。这里以分 P 输入框为准，任务完成后可保存到电脑，页面创建的任务不会自动发到 QQ。

下载限普通 BV／AV 视频，不包含番剧下载、直播录制或付费内容解锁。480P 及以上优先选择不超过设置上限的 H.264 画面与 AAC 音轨，再用 FFmpeg 合并。任务会显示目标与实际清晰度；接口只返回较低兼容流时，会明确提示降级。

## 直播通知

1. 打开 **直播订阅**，输入 UP 主 UID、直播间号或对应链接。
2. 填写通知 QQ 群号，勾选开播／下播通知，验证并保存订阅。
3. 开启直播检测并保存通知设置。新安装默认关闭直播检测。
4. 按需添加每日检测时段，最多 12 段，固定使用北京时间；例如 `12:00–14:00`、`19:00–23:30`。

时段支持跨午夜，重叠部分不会增加检测次数。关闭时段限制即全天检测。默认每轮结束后等待 60 秒，已检测到开播的主播会在时段结束后继续跟踪，直到连续两次确认下播。

| 操作 | 行为 |
| --- | --- |
| 手动开始检测 | 对当前启用订阅开始检测，可超出时段，仍遵守请求间隔和风控冷却 |
| 手动停止检测 | 停止后续直播查询，重启后保持停止 |
| 恢复自动时段 | 恢复按时段和持续跟踪设置运行 |
| 手动发开播／下播 | 页面内核对主播和目标群，再确认发送；使用已缓存房间资料，不请求 B站 |
| 仅补发此群 | 对失败或结果未知的记录，仅向原群补发原消息 |

首次或重新启用时只记录当前状态，不补发已经在进行的直播；需要时可手动发开播。手动通知不会修改真实检测状态，也不会恢复被停止的检测。发送超时可能已经送达，请先核对群消息再补发。

### 通知卡片

![开播卡片](docs/images/card-start-amis.png)

开播／下播默认渲染成图片卡片，文案用《鸣潮》角色**爱弥斯**的口吻（星炬学院学生、隧者适格者、电子幽灵，官方性格描述为「活泼俏皮」），可选软萌或朴素口吻。

卡片由外部文转图服务渲染，插件本身不内置浏览器：

```sh
docker run -itd -p 8999:8999 soulter/astrbot-t2i-service:latest
apt-get install -y fonts-noto-cjk fonts-noto-color-emoji
```

在 **直播订阅 → 通知卡片** 填写服务地址（同机部署通常是 `http://127.0.0.1:8999`），然后点「渲染服务自检」确认出图正常。服务不可用时按「卡片 → 封面 + 文案 → 纯文字」逐级降级，**不会漏通知**。

自备贴纸放进 `assets/card/custom/`，文件名以 `top-`／`tag-`／`corner-` 开头即可自动叠加。

详细规则见[直播检测与通知](docs/live.md)。

## 常用默认设置

| 设置 | 默认值 |
| --- | --- |
| 群聊／私聊识别 | 开启 |
| 同一内容重复回复间隔 | 120 秒，按会话分别计算 |
| 单消息解析上限 | 2 个 |
| 下载方式／清晰度上限 | 仅指令／480P |
| 单视频大小／时长上限 | 100 MB／600 秒 |
| 下载任务总超时 | 300 秒 |
| 下载缓存容量／保留时间 | 512 MB／6 小时 |
| 下载排队上限 | 总共 3 个任务，顺序执行 |
| 请求最小间隔／风控冷却 | 1,500 毫秒／至少 300 秒 |
| 直播检测 | 默认关闭；开启后间隔默认 60 秒 |
| 调试日志 | 默认关闭，错误和手动通知日志保留 |

下载缓存容量必须至少为单视频上限的两倍，为合并预留空间。完整默认值见 [`lib/config.mjs`](lib/config.mjs)。

## 数据与日志

配置路径由 NapCat 的 `ctx.configPath` 提供；会话、直播订阅和下载数据优先存入 `ctx.dataPath`，未提供时使用配置目录旁的 `bili-recognizer-data`。

- `bili-session.json`：账号 Cookie、设备与会话信息。
- `live-subscriptions.json`：直播订阅、状态和通知记录。
- `downloads/`：下载文件与任务元数据。
- 解析记录、概览统计和最近运行日志主要保存在内存，重载后重新开始。

发布源码时不要带上实际配置、账号文件或下载数据。本仓库已提供 [`.gitignore`](.gitignore)；提交问题时可使用脱敏诊断，仍请核对是否含个人信息。

## 开发、测试与源码目录

源码使用 Node.js ESM，前端为原生 HTML／CSS／JavaScript；只有保留的上游模块和二维码库使用 CommonJS。

| 路径 | 内容 |
| --- | --- |
| `index.mjs` | NapCat 插件入口与生命周期 |
| `lib/` | 识别、接口、会话、下载、直播、WebUI 后端与第三方代码 |
| `webui/` | 无需编译的控制台资源 |
| `test/` | 自动测试与模拟上下文 |
| `tools/` | 服务器诊断与安装包打包工具 |
| `scripts/` | 本地性能对照脚本 |
| `docs/` | 使用、排错、开发和发布说明 |

在源码目录执行：

```sh
npm test
npm run benchmark
```

完整测试需要本机 FFmpeg／ffprobe，并包含本地 HTTP 服务测试；没有 FFmpeg 时真实合并测试会跳过。当前 1.5.2 已通过 169 项本地测试，外部 B站和 NapCat 接口使用模拟响应，不能等同于所有服务器上的实机验证。详见[开发与验证](docs/development.md)。

1.4.2 减少了未变化列表的重绘、空闲轮询、会话重复写盘与诊断传输。可复现的计数与边界见[性能说明](docs/performance.md)。
